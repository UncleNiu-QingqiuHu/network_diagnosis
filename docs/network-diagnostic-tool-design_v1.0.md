## 2. 产品目标与典型场景

**输入**：目标（IP 或域名）、可选端口列表、少量诊断选项（超时、次数、IPv4/IPv6 等）。

**输出**：结构化结果（端口可达性、延迟摘要、失败原因线索）+ **与测试时间窗对齐的抓包文件**（或基于抓包的简要统计），便于事后在 Wireshark 里打开分析。

**典型场景**：排查「某端口在公网/内网是否通」、DNS 是否正常、中间设备是否 RST/不可达、TLS/应用层问题前的连通性基线。

---

## 3. 总体编排思路（推荐）

用一个小型**编排器**（以后可以是桌面 GUI、CLI 或 Web 后端任务）做三件事：

1. **解析与校验**：规范化目标是 FQDN 还是字面 IP；端口列表；是否先做 DNS 解析并记录结果（A/AAAA）。
2. **启动抓包（可选项）**：在「开始探测前」启动抓包，在「探测结束」后停止并落盘。
3. **执行 tcping**：对每端口跑一轮或若干轮；把 stdout/stderr、退出码、起止时间戳记下来，和抓包时间窗对齐。

**要点**：抓包与 tcping 必须在时间上重叠；日志里写明抓包文件路径、探测起止时间、本机出口网卡。

## 4. tcping.exe 集成要点

**职责**：以 TCP 握手（或选用的模式）为主，给出「通/不通、延迟、连续探测统计」，比 ICMP ping 更贴近「端口服务是否在监听/是否被防火墙丢包」。

**设计建议**：

- **调用模型**：子进程执行，设置工作目录与环境（避免路径问题）；超时控制在 UI 可接受范围。
- **多次采样**：默认连续 N 次（例如 5～10 次），输出成功率、min/avg/max RTT、失败类型（超时、拒绝、复位等——取决于 tcping 版本输出格式）。
- **解析策略**：不依赖肉眼读控制台；优先机器可读输出（若 tcping 支持 JSON/CSV 则使用；否则对稳定文本格式做解析，并做好版本兼容说明）。
- **IPv4/IPv6**：若用户给域名，明确解析到 A 还是 AAAA，或两者都测（分开会话更清晰）。
- **权限**：一般 tcping **不需要**管理员权限；若未来叠加 raw socket 类工具再另说。

## 5. Wireshark 集成：GUI 自动化 vs CLI

**现实约束**：Wireshark GUI 适合人手分析，不适合稳定自动化；自动抓包更稳妥的是 **带 `tshark` 的 Wireshark 命令行**（安装是同套件，调用方式不同）。

**建议分两层**：

| 模式 | 适用 | 说明 |
|------|------|------|
| **tshark 自动抓包（推荐默认）** | 产品自动化 | 可起止、可筛选、可写 pcapng、可事后导出统计 |
| **启动 Wireshark 并加载 pcap（可选）** | 高级用户 | 探测结束后用系统默认方式打开文件，减少「自动点 GUI」的脆弱性 |

**抓包参数规范（建议）**：

- **接口选择**：自动选默认路由网卡，或允许高级用户指定接口名（Windows 上名称较折腾，需在 UI 里引导）。
- **过滤器（可选）**：按 `host <目标解析后的IP>` + `tcp port <port>` 缩小体积（注意：过滤器可能让用户误以为自己「没抓到包」，需在文案中解释）。
- **落盘**：`pcapng` + 带时间戳文件名；同一次任务一个目录（任务 ID）。
- **权限**：某些接口/环境可能需要提升权限；产品里明确「抓包失败时的降级策略」（例如仅 tcping，不动 tshark）。

---

## 6. 「诊断」自动化程度分层

建议拆成三层，避免过度承诺：

1. **确定性事实层（必做）**：tcping 结果、DNS 解析结果、抓包是否存在 SYN/SYN-ACK、是否 RST、是否重传、是否握手完成。
2. **启发式结论层（可做）**：例如「对端无 SYN-ACK → 更像路径/防火墙/目标未监听」「有 RST → 像主动拒绝」「只有客户端重传 → 像黑洞/丢包」。此类结论需标注置信度与前提。
3. **应用层协议解码（慎做）**：除非明确要支持 HTTPS/SMB 等，否则第一版不把 Wireshark 解码栈产品化。

**第一版建议**：事实 + 少量高置信规则；复杂结论由用户在 Wireshark 中确认。

---

## 7. 并发、时序与资源

- **同端口多次 tcping**：串行最稳；并行会干扰抓包阅读并增加本机负载。
- **多端口**：可串行逐端口（单抓包文件内多端口的过滤显示），或每端口独立一轮抓包（文件更清晰、体积更可控）。**默认推荐**：单文件 + 串行端口。
- **磁盘与隐私**：抓包可能含敏感 payload；需提示用户，并可提供「仅抓握手前几包」等高级选项（若支持包数量截断/停止条件）。

---

## 8. 依赖、分发与合规

- **路径**：`tcping.exe`、`tshark.exe` 可能不在 PATH；建议配置页指定安装目录，或安装器检测常见路径。
- **许可**：Wireshark/tshark 与第三方 tcping 的许可证需在「关于」页呈现（尤其若打包分发）。
- **企业环境**：部分机器禁止抓包或禁止安装驱动（Npcap）；需友好失败与替代路径（仅端口探测）。

---

## 9. 第一版范围（MVP）

- 输入：目标 + 1～N 端口 + 次数/超时
- DNS：显示解析结果与选用地址族
- tcping：结构化结果（成功/失败摘要 + 原始输出归档）
- 抓包：默认 `tshark` 输出 `pcapng`，可选过滤器；结束后可选打开 Wireshark
- 报告一份汇总（HTML / Markdown / JSON 择一）：字段与文件路径

## 10. 待拍板的产品决策

以下内容会影响实现形态，后续版本可收敛为「已决议」：

1. **tcping 语义**：仅 SYN 握手完成，还是连到应用层？
2. **抓包粒度**：每次任务一个 pcap，还是每端口一个 pcap？
3. **是否默认管理员权限**：不强制时 Npcap/某些接口对抓包成功率的影响如何兜底？
4. **受众**：偏运维一键报告，还是偏研发自助（更强调 pcap 与原始字段）？
