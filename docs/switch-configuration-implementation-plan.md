# 交换机配置功能实现方案（COM / SSH）

本文档描述「交换机配置」页面的技术实现思路，覆盖 **串口（COM）** 与 **SSH** 两类连接方式；与当前 **ttkbootstrap 桌面工具** 形态对齐。**方案说明性质**，不含具体代码。

**结论摘要**：**SSH 侧推荐并应默认使用伪终端（PTY）** 承载交互式 shell，使设备端行为与真实终端一致；**串口侧**一般为直连字符流，不强行套 OS 级 PTY，但在会话层仍按「类终端」读写与展示，可与 SSH 共用同一套会话调度。

---

## 1. 目标与边界

### 1.1 目标

在「交换机配置」页中，使用户能够连接交换机并执行 **交互式 CLI**（查看状态、修改配置），体验接近小型终端 / Console。

### 1.2 建议边界（第一版）

- **不做** 完整网管平台（拓扑、告警、配置模板引擎等可后续迭代）。
- **不做** 各厂商「自动解析命令输出」的配置下发向导（后续可通过 Netconf / 专用适配器扩展）。
- **优先** 保证：串口 Console 与 SSH 登录后，**字符界面稳定、可复制、可清屏**，与常见交换机 CLI 行为兼容。

---

## 2. 总体架构（三段式）

### 2.0 推荐：伪终端（PTY）与「类终端」会话

| 链路 | 是否使用 PTY | 说明 |
|------|----------------|------|
| **SSH** | **是（推荐且默认）** | 通过客户端库在 SSH 通道上 **请求 PTY**，再 `invoke_shell`（或等价 API）。设备将把会话当作 TTY：分页、`--More--`、行编辑、与 **TERM**（如 `xterm`、`vt100`）相关的输出才与 PuTTY / 串口 Console 体验一致。**不推荐** 把 `exec_command` 无 PTY 跑单条命令当作交换机配置页的主交互路径——易出现无分页、菜单式 CLI 异常或行为与真机不一致。 |
| **串口（COM）** | **通常否（无需 OS PTY）** | 链路是 **异步串行字节流**，没有 SSH 那种「对端 PTY 协商」；实现上一般 **直接 read/write 串口**。语义上仍建议按 **终端会话** 处理（行缓冲策略、可选本地回显、滚屏与后续 ANSI）。会话层可与 SSH **共用**「读线程 + 写线程 + UI 刷新」模型，仅在连接层区分数据来源。 |

**窗口尺寸**：SSH 申请 PTY 后，宜在连接建立后向对端 **发送终端行/列（如 `resize_pty`）**，避免部分设备在默认 80×24 之外的排版问题；具体 API 随 Paramiko 等库而定。

### 2.1 连接层（Connection）

- 抽象接口：`connect()` / `disconnect()` / `is_connected`（及与读写相关的最小协议）。
- 两种实现：**SerialConnection**、**SSHConnection**，对外暴露统一的「面向字节/文本的收发」契约。

### 2.2 会话层（Session / Reader–Writer）

- 后台线程（或独立 worker）**阻塞读取**（串口 `read`、SSH channel `recv`），数据进入 **线程安全队列**。
- UI 线程通过 `after()` 定时从队列取出数据，追加到 `Text`（或后续终端控件）。
- 用户输入：由 UI 写入「待发队列」，写线程调用 `write`（串口 `write`、SSH `send`）。
- **编码**：默认 UTF-8；必要时 UI 提供可选编码（如厂商页、`latin-1`），第一版可先固定 UTF-8 + 简单可配置项。

### 2.3 表现层（GUI）

- **顶栏**：连接方式（COM / SSH）、参数表单、连接/断开、状态指示。
- **主体**：**终端显示区**（等宽字体、可滚动；可选「仅追加显示」模式）。**SSH 时**底层会话为 **PTY + 交互 shell**；**串口时**为原始字节流在界面上的终端式呈现。
- **本地回显**（可选）：串口侧部分 Console **不回显**，可由 UI 提供「本地回显用户输入」，避免误以为未键入；**SSH 在 PTY 模式下** 通常由对端回显，一般不必本地回显。

串口与 SSH 的差异集中在连接层，**会话层与 UI 逻辑共用**；后续若扩展 Telnet，可沿用同一套会话抽象。

## 3. COM（串口）方案要点

| 项目 | 说明 |
|------|------|
| 端口枚举 | Windows 下列出 `COMx` 及友好名称（可选借助 WMI 增强）；允许用户手动填写如 `COM3`。 |
| 参数 | 波特率（如 9600 / 115200）、数据位、校验、停止位、流控（RTS/CTS、XON/XOFF）；提供「常见 Console 预设」。 |
| 实现库 | **PySerial**（成熟、跨平台；以 Windows 为主场景足够）。 |
| 线程与资源 | 独立读线程 + UI 刷新；断开时必须正确 `close()`，避免 COM 长期占用。 |
| 回显 | 部分设备不回显输入；通过「本地回显」选项改善体验。 |

---

## 4. SSH 方案要点

| 项目 | 说明 |
|------|------|
| 实现库 | **Paramiko** 与现有 Tk + `after` 线程模型较易集成（或 **asyncssh**，若统一 asyncio 再评估）。 |
| Channel | **必须**走 **PTY + 交互式 shell**（如先请求 PTY 再 `invoke_shell`）：这是本方案的 **推荐主路径**，使对端按真实终端处理分页、`--More--`、行编辑与 TERM 相关输出。避免在无 PTY 的 `exec_command` 上堆叠「假交互」。 |
| 认证 | 密码、私钥路径、可选密钥口令；第一版可不做复杂键盘交互多因子，后续再补。 |
| 主机密钥 | 默认 **明确策略**：首次连接提示指纹、维护 **known_hosts**（存用户配置目录），避免静默信任任意主机。 |
| 健壮性 | Keepalive、读写超时；登录或 KEX 较慢时在 UI 显示「连接中」状态。 |
| 编码 | 以 UTF-8 为主；乱码时由 UI 编码选项兜底（与会话层一致）。 |

## 5. UI 与交互建议

### 5.1 顶栏表单

- 通过 **Tab** 或 **单选** 切换：**串口** | **SSH**。
- **串口**：端口、波特率、流控等。
- **SSH**：主机、端口（默认 22）、用户名、密码或密钥路径、终端类型（如 `xterm` / `vt100`）可选。

### 5.2 主区域

- 大型只读 `Text` 显示输出，按键/粘贴发送到会话；或后续升级为有限 ANSI 支持。
- **第一版** 可不强求完整 ANSI 仿真；若需求强烈，再评估 `pyte` + Canvas 等方案。

### 5.3 状态

展示：未连接 / 连接中 / 已连接 / 错误摘要；错误详情支持复制。

### 5.4 配置档案（后续版本）

- 保存主机、串口参数等到本地 JSON。
- **密码**：避免明文落盘；优先 OS 凭据存储，或仅保存主机与用户、不保存密码。

## 6. 依赖与工程组织

- 在 `pyproject.toml` 中增加例如：**pyserial**、**paramiko**（版本范围需约束，避免已知安全问题旧版本）。
- 在 `network_diagnosis` 下新增子包（如 `network_diagnosis/switch_console/`），将连接与会话逻辑与 **`main_app.py`** 解耦；GUI 仅负责挂载「交换机配置」页的 Frame 与控制逻辑绑定。

---

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| Tk `Text` 对 ANSI / 光标控制支持弱 | 第一版定位为「实用型控制台」；复杂 TUI 分阶段迭代。 |
| COM 权限或占用 | 明确错误提示；断开时释放句柄。 |
| SSH 安全 | known_hosts + 指纹确认；日志与界面中勿打印明文密码。 |
| 线程与生命周期 | 断开时设取消标志，读线程优雅退出，避免在已销毁 Widget 上更新。 |

---

## 8. 推荐落地顺序

1. **SSH：PTY + 交互式 shell + 终端显示区**（含必要时的终端行列设置；贴近网工习惯，联调成本低）。
2. **串口：直连读写 + 复用同一会话层与终端 UI**。
3. 再迭代：连接档案、端口扫描、ANSI 增强、厂商预设模板、Jump Host（ProxyCommand）等。

---

## 9. 可选扩展（按需收紧需求）

若第一版需支持 **固定厂商 CLI**（如华为 / 华三 / Cisco 的提示符约定）或 **跳板机（Jump Host）**，应在实现前单独补充：

- **ProxyCommand / 跳板** 在 Paramiko 中的连接链设计；
- **提示符探测** 与简单自动化（如登录后 `enable`）的幂等与超时策略。
