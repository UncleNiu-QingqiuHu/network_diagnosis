## 2. 实现形态（已定）

- **桌面 GUI**：面向运维/技术支持的单机工具，本地执行探测与（可选）抓包，结果在界面展示并可导出报告。
- 编排逻辑（校验目标 → 可选起抓包 → tcping/其它探针 → 汇总）由 GUI 应用驱动；**不依赖用户自行配置 PATH 来找到 tcping**（见第 4、8 节）。

---

## 3. 产品目标（三类，已定）

| 类别 | 含义 | 主要手段（规划） |
|------|------|------------------|
| **网络连通性** | 本机到目标是否「能到达」、名字能否解析、路径大致是否通 | DNS 解析；ICMP ping（可选，受防火墙影响）；可选 traceroute |
| **网络质量** | 延迟与稳定性，而非仅「通/不通」 | 多次采样 RTT（ping / tcping）；抖动、成功率（等价丢包倾向）；可选结合抓包看重传 |
| **端口连通性** | 指定 TCP 端口是否开放、握手是否完成、拒绝或黑洞形态 | **tcping.exe**（项目内置），按端口批量/串行探测 |

**典型场景**（继承 v1.0）：公网/内网端口是否通、DNS 是否正常、中间设备 RST/黑洞、为上层协议问题建立基线。

---

## 4. tcping 集成策略（已定）

- **tcping 可执行文件随项目分发**（安装目录或应用目录下固定相对路径调用），**不依赖**用户本机是否单独安装 tcping、也不依赖 PATH。
- 版本锁定：发布包内附带**固定版本**的 `tcping.exe`，并在「关于/诊断信息」中展示该版本，便于排障与解析输出格式。
- 调用与解析要求仍适用 v1.0：子进程、超时、多次采样、优先机器可读输出、IPv4/IPv6 策略、归档原始 stdout/stderr。

## 5. Wireshark / tshark / Npcap 获取方式（v1.2 已定）

### 5.1 决策概述

- **不在主程序目录内散装 tshark 及其大量依赖 DLL**；改为：产品**附带经团队选定的 Wireshark 官方 Windows 安装包**（或与安装介质同目录分发），由 **GUI 引导用户启动该安装程序**完成安装。
- 官方安装向导通常会一并安装 **Wireshark GUI、tshark CLI**，并**引导安装 Npcap**（用户可在向导中勾选/确认）。在用户**同意并完成安装**后，可同时满足自动抓包对 **可执行文件** 与 **抓包驱动** 的两类前提。
- 应用侧通过 **检测** 标准安装路径下的 `tshark.exe`（例如常见的 `%ProgramFiles%\Wireshark\tshark.exe`，以及 32 位或自定义路径等变体）决定是否启用抓包；未检测到时展示明确指引：**「一键打开已附带的 Wireshark 安装包」**（或打开说明页 + 校验和，视分发策略而定）。

### 5.2 为何该方案能「一并解决」主要矛盾

| 问题 | 该方案的应对 |
|------|----------------|
| 用户未装 tshark、PATH 未配 | 官方安装落到固定目录，应用主动探测绝对路径调用 |
| Npcap 缺失导致抓不了包 | 官方安装流程集中处理 Npcap，减少「只拷贝 exe 忘记驱动」的售后 |
| 用户还需用图形界面深入分析 | 同类安装已带 Wireshark GUI，便于直接打开本工具生成的 pcap |

### 5.3 仍须面对的限制（产品层需兜底的）

- **仍需用户交互与通常在安装时具备管理员权限（UAC）**；用户拒绝安装或企业策略禁止安装时，抓包能力不可用 → **必须保留无抓包降级**（tcping + DNS + ping 等仍可用）。
- **主程序或介质体积增大**；可选变体：**首次启用抓包时再下载**官方包（需 HTTPS、哈希校验、断点续传与失败提示），以缩小初次安装包 —— 作为实现分支，在实现阶段择定。
- **版本漂移**：用户日后自行升级/降级 Wireshark 可能导致 CLI 行为差异；报告与「关于」中应**记录实际探测到的 tshark 版本**，文档中可标明**当前发布经过验证的 Wireshark 主版本**。
- **许可与再分发**：捆绑或托管官方安装包须遵守 Wireshark 的许可证与官方对再分发的说明（以 [wireshark.org](https://www.wireshark.org/) 与法务审查为准）；**关于**页中保持第三方致谢与许可证说明。
- **静默/批量部署**：若未来面向 IT 批量装机，可另案评估官方安装器静默参数与组策略场景；**当前默认以交互式引导安装**为主叙事。

### 5.4 与自动化抓包的关系

- 抓包执行方式不变：仍以 **tshark（CLI）** 按 v1.0 规范起止、写 `pcapng`、可选显示过滤器；**可选**在任务结束后用 **Wireshark GUI** 打开同一 pcap。
- **唯一变化**：`tshark.exe` 来自 **用户通过本工具引导安装的 Wireshark**，由应用**探测路径**，而非随主程序目录携带 `tshark.exe`。

## 6. 诊断应从哪些维度开展（建议清单）

下列维度可按 **「本地环境 → 名字与路由 → 连通与质量 → 端口 → 可选抓包事实」** 顺序在 GUI 中分区展示，便于用户自上而下缩小范围。

### 6.1 本机与出口上下文（Local Context）

- **活动网卡**：名称、类型、是否启用；可选：当前选用哪块网卡做探测（高级）。
- **本机 L3 信息**：IPv4/IPv6 地址、子网掩码前缀、**默认网关**。
- **DNS 配置**：当前系统使用的 DNS 服务器列表（仅展示事实，不替代解析测试）。
- **备注**：若存在多网卡/VPN/代理，可用简短提示「结果仅代表当前路由选路下的路径」（代理深层检测可后延）。

### 6.2 名字解析（DNS）

- **解析结果**：A / AAAA 记录、解析到的 IP 列表；解析耗时。
- **失败形态**：NXDOMAIN、超时、无响应等（取决于实现）。
- **与探测一致**：端口与质量类探针实际使用的目标 IP（及地址族）应在报告中写明，避免域名解析变化造成误解。

### 6.3 基础连通性（Reachability）

- **ICMP Ping**（可选模块）：若目标允许 ICMP，可看是否可达；若不允许，界面需标注「ICMP 被禁不代表 TCP 不通」。
- **Traceroute**（可选、进阶）：路径上每一跳的时延与是否超时，辅助判断阻断大致区段；实现成本与权限需单独评估，可作为后续版本能力。

### 6.4 网络质量（Quality）

- 基于 **多次 ping**（若启用）与 **每端口多次 tcping**：
  - **RTT**：最小 / 平均 / 最大（或百分位，可后延）。
  - **成功率**：成功次数 / 总次数，作为**连通稳定度**指标。
  - **抖动**：相邻 RTT 差分的统计（简易 jitter），用于粗评稳定性。
- **说明**：质量结论应区分「ICMP 质量」与「TCP 某端口质量」，二者可能不一致。

### 6.5 端口连通性（Port / Service Reachability）

- 针对用户输入的每个端口：
  - **是否完成 TCP 握手**（或 tcping 定义的等价成功条件）。
  - **失败分类**（依据 tcping 输出与可选抓包）：超时（似黑洞）、RST（似拒绝或未监听）、其它异常。
  - **该端口的 RTT 与成功率**（与 6.4 对齐展示）。

### 6.6 抓包层事实（可选，依赖用户已安装的 Wireshark + Npcap）

在 **已检测到 tshark 且 Npcap 工作正常**、且抓包与探针时间对齐的前提下，可提供**确定性事实**（不过度解读应用层）：

- 是否观察到 **SYN / SYN-ACK / RST / FIN** 等与本次端口相关的报文。
- **重传**是否存在（粗粒度计数或标记）。
- 输出 **pcapng 路径** 供人工在 Wireshark 中深入分析。

启发式结论（防火墙 vs 未监听等）仍建议标注置信度，见原 v1.0「自动化程度分层」。

### 6.7 报告与可观测性（元数据）

- **任务 ID、时间范围**、每段探测起止时间；**内置 tcping 版本**；**检测到的 tshark/Wireshark 版本**（若已安装）；是否启用抓包及是否降级。
- 原始**控制台输出**归档路径或内嵌片段，便于售后复现。

## 7. 总体编排思路（继承并贴合 GUI）

1. **解析与校验**目标与端口列表；可选先跑 DNS 并展示 6.2。
2. **（可选）若用户启用抓包**：
   - 若未检测到可用 `tshark`/Npcap：提示并**引导启动附带的 Wireshark 安装包**；用户可取消 → 本轮不抓包。
   - 若已就绪：按 v1.0 规范启动 tshark（使用探测到的绝对路径）。
3. **执行探针**：ping（可选）→ 按端口 tcping（串行多端口建议默认保留）。
4. **停止抓包**并落盘；汇总 6.x 各维度到 GUI 与导出报告。
5. **降级路径**：安装被拒、tshark 启动失败、Npcap 异常等，均给出明确状态；**核心诊断（6.1～6.5）不依赖抓包**。

## 8. 依赖、分发与合规（v1.2 更新）

- **tcping**：与主程序一起发布，相对路径加载。
- **Wireshark（含 tshark、安装向导中的 Npcap 引导）**：以**官方安装包**形式随产品分发或由产品**按需拉取**；遵守再分发与许可证要求；安装后由程序**自动探测** `tshark.exe`。
- **企业环境**：禁止安装 Wireshark/Npcap 时，产品仍应在**无抓包**模式下完整提供 6.1～6.5 的核心价值。

---

## 9. 第一版范围（MVP，v1.2 更新）

- 桌面 GUI；输入目标、端口列表、次数/超时、可选 IPv4/IPv6 策略。
- 内置 tcping；展示 **6.2（DNS）+ 6.5（端口）** 为必需；**6.4（质量）** 至少基于 tcping 多样本；**6.3 ping** 建议 MVP 即做（系统 ping 或自带组件择定）。
- 抓包：**探测已安装的 tshark + Npcap** 则启用；否则展示**引导安装**（启动附带 Wireshark 安装包或等价流程），失败则降级。
- 报告：导出一份结构化结果（JSON 或 HTML 择一亦可）+ 原始日志引用路径。

## 10. 待拍板的产品决策（v1.2）

1. **tcping 语义**：仅完成握手，还是建立到应用层可读状态（若工具支持）？
2. **抓包粒度**：单次任务单 pcap vs 每端口 pcap。
3. **Wireshark 分发形态**：安装包**随主程序一并打包** vs **首次启用抓包时下载**（及 CDN、哈希校验策略）。
4. **技术栈**：桌面 GUI 框架（如 .NET WPF/WinUI、Qt、Electron 等）与总体安装包大小上限。
5. **ICMP/traceroute**：MVP 是否包含系统 `ping`；traceroute 是否排入后续版本。
