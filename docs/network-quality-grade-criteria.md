# 网络质量档位评判标准

本文档描述本工具在 **`network_diagnosis/quality_assessment.py`** 中 `compute_network_quality` 所采用的综合档位逻辑，供产品与运维对照。档位输出为：**极佳**、**正常**、**较差**、**堵塞**。

> **说明**：实现若有调整，以源码为准；修订本文档时请同步对照该函数。

---

## 1. 数据来源与指标含义

### 1.1 DNS（前置条件）

- 若 **DNS 解析失败**或 **无可用地址**：不再计算丢包/时延/抖动，**综合档位固定为「堵塞」**（指标行中会标明 DNS 失败）。

### 1.2 丢包率（`loss_pct`）

按以下 **优先级** 取值（二选一为主，再与 UDP 合并）：

1. **ICMP Ping**：启用 Ping 且 `attempted > 0` 时，`loss_pct = 100% × lost / attempted`，依据为「ICMP Ping」。
2. **TCP 连接抽样（tcping）**：未使用上述 Ping 丢包、且用户 **配置了端口** 并有端口结果时，`loss_pct` 为所有端口样本中 **连接失败占比**，依据为「TCP 连接尝试（tcping 抽样）」。

**与 iperf3 UDP 合并（可选）**

- 当 **带宽模式相关选项** 启用「将 iperf3 UDP 纳入网络质量综合判定」且 **UDP 抽样成功**（`iperf_udp_quality.ok`）时：
  - 若 UDP 给出了丢包率，则与当前 `loss_pct` **取较大值** 作为最终用于判定的丢包率；
  - 若原先无丢包率，则 **直接使用 UDP 丢包率**；
  - 文案中会标注已与 **iperf3 UDP 合并（取较差）**。

### 1.3 平均时延（`avg_lat`，毫秒）

1. 若有 Ping RTT 样本：取 **ICMP RTT 算术平均**，依据「ICMP Ping RTT」。
2. 否则若有 tcping 成功 RTT：取 **TCP 握手 RTT 算术平均**，依据「TCP 握手 RTT（tcping）」。

### 1.4 抖动（`jitter_ms`，毫秒）

1. **Ping**：有至少 1 个 RTT 时，使用 **相邻 RTT 差分绝对值的平均**（IPDV 近似）；仅 1 个样本时抖动近似为 0，依据标注「ICMP」或「ICMP（单样本，抖动近似）」。
2. **tcping**：无 Ping 抖动来源时，若有至少 2 个成功 RTT，使用 **RTT 样本标准差**，依据「TCP RTT 波动（tcping）」。

**与 iperf3 UDP 合并（可选）**

- 与 UDP 抽样成功时的 **UDP 抖动** 取 **较大值**；若原先无抖动样本则采用 UDP 抖动。依据中会标注已与 **iperf3 UDP 合并（取较差）**。

### 1.5 端口状态（用户配置了端口时）

- **`all_ports_bad`**：所测端口结果 **全部为** 非 `OK`。
- **`some_ports_bad`**：存在 **任意** 端口非 `OK`。
- **`bad_ports`**：`failure_class` 属于 **超时（TIMEOUT）、不可达（UNREACHABLE）、探测异常（ERROR）** 的端口（用于「较差」分支）。

### 1.6 Ping「硬失败」（`ping_hard_fail`）

- 条件：启用了 Ping；`attempted > 0`；**`received == 0`**（全部未收到成功回复）。

### 1.7 带宽 / 吞吐量（HTTP、iperf3 TCP 等）

- **仅写入「带宽/吞吐量」说明与指标行**，用于描述抽样结果；
- **不参与** 下列档位 **if/elif** 判定（Mbps 高低不会改变极佳/正常/较差/堵塞的规则）。

### 1.8 iperf3 UDP 辅助行

- 启用 UDP 质量选项时，指标中会追加 **「iperf3 UDP（质量辅助）」** 摘要行。
- 若 UDP **抽样失败**：该行说明失败，**丢包/抖动不并入档位**（仍以 ICMP/tcping 为准）。

## 2. 档位判定规则（按源码顺序）

以下为 **互斥分支**：自上而下 **先满足条件者为准**（均为在 DNS 已解析成功的前提下）。

### 2.1 堵塞

满足 **任一**：

| 条件 |
|------|
| 用户配置了端口，且 **所有端口** 探测结果均非 `OK` |
| Ping 硬失败，且（**无丢包率统计** 或 **丢包率 ≥ 25%**） |
| **丢包率 ≥ 15%** |
| **平均时延 ≥ 400 ms** 且 **丢包率 ≥ 5%** |

### 2.2 较差

在未被判为 **堵塞** 的前提下，满足 **任一**：

| 条件 |
|------|
| **丢包率 ≥ 5%** |
| **平均时延 ≥ 150 ms** |
| **抖动 ≥ 40 ms** |
| 存在 **部分端口异常**，且至少有一个端口属于 **超时 / 不可达 / 错误**（`bad_ports` 非空） |
| Ping 硬失败，且用户 **未配置** 端口探测 |

### 2.3 极佳

在未被判为 **堵塞**、**较差** 的前提下，**同时**满足：

| 条件 |
|------|
| **丢包率 ≤ 2%** |
| **平均时延 ≤ 70 ms** |
| **无抖动样本** 或 **抖动 ≤ 25 ms** |
| **不存在「部分端口异常」**（`some_ports_bad` 为假） |

### 2.4 正常

以下 **任一** 成立时为 **正常**（且未被更高优先级档位命中）：

| 条件 |
|------|
| **未启用 Ping** 且 **未配置端口** |
| **既无平均时延样本，也无丢包率样本** |
| 其余未落入极佳 / 较差 / 堵塞的情形 |

---

## 3. 报告中的展示

- **`metric_lines`**：面向 GUI / Markdown「网络质量与指标」小节逐条列出丢包、时延、抖动、带宽说明及可选 UDP 辅助行。
- **`grade`**：上述判定得到的档位字符串。
- **`loss_pct` / `avg_latency_ms` / `jitter_ms`**：为 **合并后** 用于展示与判定的数值（可能与单项探测原始值不同）。
