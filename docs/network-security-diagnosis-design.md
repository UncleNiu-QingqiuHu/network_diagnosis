# 网络安全诊断功能设计方案（面向企业网管）

本文档描述在「青丘狐网络工作台」类桌面工具中增加 **网络安全诊断** 能力时的功能规划、边界与落地优先级，**主要读者为企业网络管理员、IT 运维与安全运营配合岗位**。

---

## 1. 目标与原则

### 1.1 目标

- 在**已授权**的内网或自有资产上，快速完成「暴露面、基础加固、解析与出口异常」类 **只读或可审计** 的检查。
- 输出形态与现有产品一致：**GUI 摘要 + Markdown 技术报告**（便于工单、变更与审计归档）。
- **不替代** 企业级漏洞管理平台、EDR、SIEM；定位是 **现场排障与轻量基线核查** 的补充工具。

### 1.2 原则

- **默认最小化**：不采集业务 payload；HTTPS 默认不解密内容。
- **授权与合规**：对「远程浅测」类能力默认关闭，启用前需明确提示仅限书面授权范围。
- **可追溯**：报告含时间、本机标识、目标范围、工具版本；关键结论标注信息来源（如 `netstat`、系统 API）。

---

## 2. 功能域概览

| 域 | 核心价值（网管视角） | 与现有能力关系 |
|----|----------------------|----------------|
| 本机暴露面 | 快速发现多绑 `0.0.0.0`、闲置高危端口 | 可与「本机进程/网络栈」类探针并列 |
| 防火墙与策略感知 | 规则是否过宽、防火墙是否被绕过 | 只读摘要 + 引导系统防火墙管理界面 |
| DNS / 解析安全 | 内外解析不一致、劫持或错误分流 | 延伸现有「指定 DNS 对比」 |
| 授权目标浅测 | TLS/证书、HTTP 安全响应头、明文协议迹象；**TCP 端口扫描与轻量服务指纹**（§3.4.1） | 延伸 HTTPS/TLS、DNS；端口扫描见 §3.4.1 |
| 出站与代理 | 是否走代理、异常外连概况 | 延伸「出口/代理」诊断 |
| 合规与基线信息 | OS 构建、密码学策略摘要等 | 适合独立报告章节 |

## 3. 功能详述（企业网管场景）

### 3.1 本机暴露面与监听分析

**能力**

- 枚举 **TCP/UDP 监听**：端口、协议、绑定地址（是否 `0.0.0.0` / `::`）、关联进程/服务名（若可解析）。
- 可选：**知名端口与风险等级提示**（仅「提示」，不断言是否可被利用）。

**网管用途**

- 服务器/运维终端临时接入后，快速确认「是否多开了管理端口」「是否绑定全网卡」。
- 与变更窗口对照：新服务上线后复核监听范围。

**实现倾向**

- Windows：`Get-NetTCPConnection` / `netstat` + 进程映射；与工作线程 + 队列回灌模式一致。

**注意**

- 进程名可能需管理员权限才完整；报告注明权限与采集盲区。

---

### 3.2 防火墙与访问控制摘要（只读）

**能力**

- **防火墙启用状态**（域/专用/公用配置文件）。
- **规则抽样**：例如任意源 + 高危端口的入站规则列表（条数上限可配置）。
- **操作建议**：一键打开 Windows 防火墙高级管理（`wf.msc`），**不在首版强制改规则**。

**网管用途**

- 桌面批量巡检时，发现「防火墙关闭」或「过于宽松」的常见误配。
- 与组策略落地结果抽检配合（工具不承担 GPO 下发职责）。

---

### 3.3 DNS / 解析安全（与内网架构强相关）

**能力**

- **多解析路径对比**：系统解析 vs 指定 DNS（沿用现有能力）；可选扩展 DoH（若产品接受额外依赖与配置）。
- **内外一致性**：同一 FQDN 在内网 DNS 与公网 DNS 的解析差异提示（**启发式**：可能为 split-DNS 设计，也可能是配置错误）。
- 谨慎使用「可疑」措辞，以 **事实并排展示** 为主。

**网管用途**

- 排查「内网应用偶发解析到公网」「新开站点未同步内部 zone」类问题。
- 与现网 **DNS 架构设计文档** 对照的人工研判入口。

---

### 3.4 授权目标的「安全浅测」（非渗透）

**定位名称建议**

- 界面与报告中使用：**安全基线探测**、**浅层安全检查**，避免让用户误解为未授权渗透。

**可选子能力（均需目标授权）**

- **TLS / 证书**：有效期、链完整性、协议版本与套件偏旧提示（客户端侧探测）。
- **HTTP 安全响应头**：`Strict-Transport-Security`、`Content-Security-Policy`、`X-Frame-Options` 等缺失提示。
- **明文协议迹象**：如明文 FTP、过时 SMB 暴露等——**仅报告事实与端口/协议标识**，不提供利用方式。
- **TCP 端口扫描与轻量服务指纹**：单主机、仅 IPv4、默认纯 Python connect 扫描，可选 nmap `-sT`；规格见 **§3.4.1**。

**网管用途**

- 对内网业务系统、DMZ 入口做变更后 **快速验收**。
- 与渗透测试报告 **不重复**：此处是低噪声、自动化友好的「门槛检查」。

**产品约束**

- 默认关闭；勾选前 **二次确认** 授权范围。
- 并发与速率限制，避免对生产造成压力（可配置）。

---

### 3.4.1 授权目标：TCP 端口扫描与轻量服务指纹

本节约定 **「授权模块」** 扩展方案：**仅 TCP**、**扫描对象为单主机**、**默认纯 Python 实现**，并可选集成 **nmap**；**不包含 IPv6**。**落地代码**：`network_diagnosis/security_diag/port_scan.py`，GUI 入口见「安全诊断 → 授权目标 → TCP 端口扫描」。

#### 定位与合规

- 与 §3.4 一致：界面与报告中使用 **安全基线探测 / 浅层安全检查** 等表述；**必须**与现有「授权目标」勾选联动，未勾选则不可用。
- 扫描行为可能被对端防火墙、IDS/IPS **记录**；界面与报告需提示用户仅在 **书面授权** 的目标上使用，并控制并发与端口规模，避免被误判为异常流量。
- **不替代** 商用漏扫；不提供漏洞利用、口令爆破、目录遍历或深度 Web 爬行。

#### 扫描对象（范围约束）

| 项目 | 首版约定 |
|------|-----------|
| 目标形态 | **单个主机**：用户填写 **FQDN / 主机名** 或 **IPv4 地址**（四段点分） |
| 解析 | 主机名仅解析 **IPv4（A 记录）**；若解析出多个 A 记录，约定 **只使用第一条**（或在报告中明示所选 IP，避免静默歧义） |
| IPv6 | **不做**：不解析 AAAA、不扫描 `::/128` |
| 网段 | **不做**：不支持 CIDR、IP 范围批量扫描 |

#### 扫描语义与技术路径

**默认路径：纯 Python（推荐、默认安装即可）**

- 采用 **TCP 连接扫描**（等价 `connect()` 完整三次握手），端口开放判定以「在超时时间内建立连接」为准。
- **并发**：线程池或 `asyncio` 等可控并行；必须提供 **最大并发数**、**单端口超时**、**整任务超时/端口数上限**，默认值偏保守。
- **输出**：与现有产品一致，写入 **Markdown**（端口、状态、往返耗时摘要、错误摘要）；可节选原始探测日志便于审计。

**轻量服务指纹（banner）**

- 在已判定开放的端口上，可选执行 **只读、短时** 的 banner 抓取（例如发送少量触发字节或无发送仅读对端首包，依端口类型文档化策略）。
- 仅呈现 **事实文本**（截断长度上限），**不做** CVE 匹配、版本推断数据库、漏洞结论。
- 对 HTTPS 等加密端口：指纹能力受限，以「已开放 TLS」级别的事实描述为主，TLS 细节继续在既有 **TLS 专项探测** 中完成。

**高级选项：nmap（可选集成）**

- **定位**：在同一授权闸门下，为已安装 nmap 的高级用户提供 **可选** 扫描后端；**默认关闭**，不因未安装 nmap 而阻断主流程。
- **前置条件**：本机 `PATH` 可发现 `nmap.exe`，或用户在高级选项中填写 **nmap 可执行文件路径**（仅本地路径校验，不捆绑二进制）。
- **参数边界（建议）**：首版仅支持 **`TCP connect`（`-sT`）**、单主机、端口列表或端口范围与 Python 路径 **语义对齐**；禁止在界面暴露任意 Shell；输出优先解析 **XML（`-oX -`）** 以保持结构化，失败时降级展示受限文本并提示人工核对。
- **权限**：`-sT` 一般 **无需管理员**；若用户自行改用需提升权限的选项，应在 UI 层禁止或二次警示（实现阶段细化黑名单）。
- **与 Python 路径关系**：同一任务 **二选一** 后端（Python **或** nmap），避免重复扫描与结果混淆。

#### 交互要点（规划）

- **输入**：目标主机（单值）；端口 —— 预设模板（如常见 Web、远程管理、数据库等 Top 列表）+ 自定义列表（校验格式与数量上限）。
- **选项**：并发、超时、是否抓取 banner、是否启用 **nmap 高级模式**（路径、`‑sT` 固定、端口参数同步）。
- **执行**：后台线程 + 可取消 + 进度（已完成端口数/总数）；错误与超时归类展示。
- **报告章节建议**：`## 网络安全诊断（授权目标 — TCP 端口扫描）`，附目标 IP、时间、授权勾选记录说明、后端类型（Python / nmap）。

#### 明确排除（与本节方案边界）

- UDP、SYN 半开等非 **connect** 语义（除非未来单独论证并在界面隔离）。
- IPv6、多主机、整网段扫描。
- 依赖 masscan 等外部引擎作为默认路径（若未来扩展，另起小节评审）。

---

### 3.5 本机出站连接与代理路径

**能力**

- **出站连接概要**：进程、远端 IP/端口（周期性快照，非全流量存储）。
- **代理检测**：系统代理、WinHTTP、PAC 等（与现有「出口/代理」能力叠加）。

**网管用途**

- 终端疑似中毒或异常外连时的 **第一反应信息**（仍须结合 EDR/SIEM）。
- 验证「策略路由 / 代理绕行」是否按设计生效。

**注意**

- 不向用户默认展示完整 URL 路径（隐私与合规）；仅元数据级。

---

### 3.6 合规与基线信息（报告向）

**能力（示例）**

- OS 构建号、安装时间摘要（若可读）。
- **TLS/密码学策略** 只读摘要（注册表/策略相关，以「信息汇总」呈现）。
- **补丁级别** 仅作参考列表头，**不替代** WSUS/SCCM/Intune。

**网管用途**

- 作为 **月度巡检附件** 或项目交付时的环境基线一页。

---

## 4. 不建议纳入首版的能力

以下能力 **法务与运维风险高**、或与现有产品边界不符，建议不作为首版范围；若未来单独产品线再评估：

- 未授权漏洞扫描、自动化利用链。
- 大规模密码/端口爆破。
- 深度 Web 漏洞爬虫与模糊测试。
- 默认 HTTPS 中间人解密。

---

## 5. 与主程序的集成方式（建议）

- **入口**：主导航新增 **「网络安全」** 独立模块，或在「网络诊断」内 **子模式**（避免单页过载）。
- **执行**：与现网一致 — **后台线程 + 队列更新 GUI**，长任务可取消。
- **报告**：Markdown 增加固定章节模板，例如：`## 网络安全诊断（本机）`、`## 网络安全诊断（目标）`，并附原始命令输出路径索引。
- **依赖**：优先系统自带与现有 `ThirdParty` 目录策略；重型引擎不捆绑进默认安装包。

---

## 6. 建议的 MVP（企业网管首版）

按 **投入产出比** 排序，建议首版交付：

1. **监听端口 + 绑定地址 + 进程映射**（本机暴露面）。
2. **防火墙状态 + 宽松规则抽样**（只读）。
3. **授权目标的 TLS + HTTP 安全响应头**（与现有探测目标模型共用）。
4. **DNS 多路径对比增强**（在现有「指定 DNS」上迭代，避免大而全重写）。

5. **授权目标 TCP 端口扫描 + 轻量服务指纹**（§3.4.1）：单主机、仅 IPv4、默认纯 Python connect 扫描；可选 nmap `-sT` 高级后端；与现有授权勾选与 Markdown 导出一致。

后续迭代再考虑：出站连接快照、DoH 对比、报告内「基线模板」与企业自定义检查项；端口扫描方向如需 IPv6/网段/UDP 须单独评审后再扩展开规格。
