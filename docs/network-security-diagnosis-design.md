# 网络安全诊断功能设计方案（面向企业网管）

本文档描述在「青丘狐网络工作台」类桌面工具中增加 **网络安全诊断** 能力时的功能规划、边界与落地优先级，**主要读者为企业网络管理员、IT 运维与安全运营配合岗位**。

---

## 1. 目标与原则

### 1.1 目标

- 在**已授权**的内网或自有资产上，快速完成「暴露面、基础加固、解析与出口异常」类 **只读或可审计** 的检查。
- 输出形态与现有产品一致：**GUI 摘要 + Markdown 技术报告**（便于工单、变更与审计归档）。
- **不替代** 企业级漏洞管理平台、EDR、SIEM；定位是 **现场排障与轻量基线核查** 的补充工具。

### 1.2 原则

- **默认最小化**：不采集业务 payload；HTTPS 默认不解密内容。
- **授权与合规**：对「远程浅测」类能力默认关闭，启用前需明确提示仅限书面授权范围。
- **可追溯**：报告含时间、本机标识、目标范围、工具版本；关键结论标注信息来源（如 `netstat`、系统 API）。

---

## 2. 功能域概览

| 域 | 核心价值（网管视角） | 与现有能力关系 |
|----|----------------------|----------------|
| 本机暴露面 | 快速发现多绑 `0.0.0.0`、闲置高危端口 | 可与「本机进程/网络栈」类探针并列 |
| 防火墙与策略感知 | 规则是否过宽、防火墙是否被绕过 | 只读摘要 + 引导系统防火墙管理界面 |
| DNS / 解析安全 | 内外解析不一致、劫持或错误分流 | 延伸现有「指定 DNS 对比」 |
| 授权目标浅测 | TLS/证书、HTTP 安全响应头、明文协议迹象 | 延伸 HTTPS/TLS、出口探测 |
| 出站与代理 | 是否走代理、异常外连概况 | 延伸「出口/代理」诊断 |
| 合规与基线信息 | OS 构建、密码学策略摘要等 | 适合独立报告章节 |

---

## 3. 功能详述（企业网管场景）

### 3.1 本机暴露面与监听分析

**能力**

- 枚举 **TCP/UDP 监听**：端口、协议、绑定地址（是否 `0.0.0.0` / `::`）、关联进程/服务名（若可解析）。
- 可选：**知名端口与风险等级提示**（仅「提示」，不断言是否可被利用）。

**网管用途**

- 服务器/运维终端临时接入后，快速确认「是否多开了管理端口」「是否绑定全网卡」。
- 与变更窗口对照：新服务上线后复核监听范围。

**实现倾向**

- Windows：`Get-NetTCPConnection` / `netstat` + 进程映射；与工作线程 + 队列回灌模式一致。

**注意**

- 进程名可能需管理员权限才完整；报告注明权限与采集盲区。

---

### 3.2 防火墙与访问控制摘要（只读）

**能力**

- **防火墙启用状态**（域/专用/公用配置文件）。
- **规则抽样**：例如任意源 + 高危端口的入站规则列表（条数上限可配置）。
- **操作建议**：一键打开 Windows 防火墙高级管理（`wf.msc`），**不在首版强制改规则**。

**网管用途**

- 桌面批量巡检时，发现「防火墙关闭」或「过于宽松」的常见误配。
- 与组策略落地结果抽检配合（工具不承担 GPO 下发职责）。

---

### 3.3 DNS / 解析安全（与内网架构强相关）

**能力**

- **多解析路径对比**：系统解析 vs 指定 DNS（沿用现有能力）；可选扩展 DoH（若产品接受额外依赖与配置）。
- **内外一致性**：同一 FQDN 在内网 DNS 与公网 DNS 的解析差异提示（**启发式**：可能为 split-DNS 设计，也可能是配置错误）。
- 谨慎使用「可疑」措辞，以 **事实并排展示** 为主。

**网管用途**

- 排查「内网应用偶发解析到公网」「新开站点未同步内部 zone」类问题。
- 与现网 **DNS 架构设计文档** 对照的人工研判入口。

---

### 3.4 授权目标的「安全浅测」（非渗透）

**定位名称建议**

- 界面与报告中使用：**安全基线探测**、**浅层安全检查**，避免让用户误解为未授权渗透。

**可选子能力（均需目标授权）**

- **TLS / 证书**：有效期、链完整性、协议版本与套件偏旧提示（客户端侧探测）。
- **HTTP 安全响应头**：`Strict-Transport-Security`、`Content-Security-Policy`、`X-Frame-Options` 等缺失提示。
- **明文协议迹象**：如明文 FTP、过时 SMB 暴露等——**仅报告事实与端口/协议标识**，不提供利用方式。

**网管用途**

- 对内网业务系统、DMZ 入口做变更后 **快速验收**。
- 与渗透测试报告 **不重复**：此处是低噪声、自动化友好的「门槛检查」。

**产品约束**

- 默认关闭；勾选前 **二次确认** 授权范围。
- 并发与速率限制，避免对生产造成压力（可配置）。

---

### 3.5 本机出站连接与代理路径

**能力**

- **出站连接概要**：进程、远端 IP/端口（周期性快照，非全流量存储）。
- **代理检测**：系统代理、WinHTTP、PAC 等（与现有「出口/代理」能力叠加）。

**网管用途**

- 终端疑似中毒或异常外连时的 **第一反应信息**（仍须结合 EDR/SIEM）。
- 验证「策略路由 / 代理绕行」是否按设计生效。

**注意**

- 不向用户默认展示完整 URL 路径（隐私与合规）；仅元数据级。

---

### 3.6 合规与基线信息（报告向）

**能力（示例）**

- OS 构建号、安装时间摘要（若可读）。
- **TLS/密码学策略** 只读摘要（注册表/策略相关，以「信息汇总」呈现）。
- **补丁级别** 仅作参考列表头，**不替代** WSUS/SCCM/Intune。

**网管用途**

- 作为 **月度巡检附件** 或项目交付时的环境基线一页。

---

## 4. 不建议纳入首版的能力

以下能力 **法务与运维风险高**、或与现有产品边界不符，建议不作为首版范围；若未来单独产品线再评估：

- 未授权漏洞扫描、自动化利用链。
- 大规模密码/端口爆破。
- 深度 Web 漏洞爬虫与模糊测试。
- 默认 HTTPS 中间人解密。

---

## 5. 与主程序的集成方式（建议）

- **入口**：主导航新增 **「网络安全」** 独立模块，或在「网络诊断」内 **子模式**（避免单页过载）。
- **执行**：与现网一致 — **后台线程 + 队列更新 GUI**，长任务可取消。
- **报告**：Markdown 增加固定章节模板，例如：`## 网络安全诊断（本机）`、`## 网络安全诊断（目标）`，并附原始命令输出路径索引。
- **依赖**：优先系统自带与现有 `ThirdParty` 目录策略；重型引擎不捆绑进默认安装包。

---

## 6. 建议的 MVP（企业网管首版）

按 **投入产出比** 排序，建议首版交付：

1. **监听端口 + 绑定地址 + 进程映射**（本机暴露面）。
2. **防火墙状态 + 宽松规则抽样**（只读）。
3. **授权目标的 TLS + HTTP 安全响应头**（与现有探测目标模型共用）。
4. **DNS 多路径对比增强**（在现有「指定 DNS」上迭代，避免大而全重写）。

后续迭代再考虑：出站连接快照、DoH 对比、报告内「基线模板」与企业自定义检查项。
