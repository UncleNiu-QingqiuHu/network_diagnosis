## 2. 实现形态（已定）

- **桌面 GUI**：本地执行探测与（可选）抓包；**界面上呈现面向非技术人员的结论**，避免堆砌术语。
- 编排逻辑（校验目标 → 可选起抓包 → tcping/其它探针 → 汇总）由 GUI 应用驱动；**不依赖用户自行配置 PATH 来找到 tcping**（见第 5、9 节）。
- **与 GUI 并列**：每次诊断任务在磁盘生成一份**完整的 Markdown 报告**，供运维 / 技术人员存档、粘贴在工单或 Wiki、Diff 追踪。两份内容**同源数据**，表述深度不同（见第 3 节）。

## 3. 诊断结果双通道（v1.3 已定）

### 3.1 定位

| 输出 | 受众 | 目标 |
|------|------|------|
| **GUI 结果** | 非技术人员（业务用户、一线客服协助场景等） | 快速看懂「有没有问题、严重吗、下一步干嘛」，少术语、强视觉引导 |
| **Markdown 报告**（`.md` 文件，约定命名与输出目录） | 运维、网络工程师、研发排查 | **完整、可追溯**：元数据、全维度数据表、原始输出引用、抓包路径、版本与时间线，便于邮件/IM/Git 粘贴 |

### 3.2 内容原则：同源、不同深度

- 底层应是**同一套结构化诊断模型**（各维度事实 + 原始日志引用），**禁止**维护两套互不相干的数据流水线。
- **GUI**：由模型映射为「摘要状态 + 通俗解释 + 可折叠的次级信息」；默认不展示完整命令行与长日志。
- **Markdown**：同一模型**序列化**为分级标题、表格、列表、代码块（原始片段）；附件路径（pcap、`tcping` 文本日志等）**写绝对路径**；可选在文末附「与 GUI 摘要一致的结语」方便交叉核对。

### 3.3 GUI 侧建议展示（非技术向）

- **总览**：例如「整体：正常 / 存在问题 / 仅部分端口异常」等少量状态，配颜色或图标。
- **人话结论**：2～5 条要点（例：「您填的地址可以解析；80 端口可以连通；443 端口多次超时——更像是对方或中间网络问题，而不是本机完全断网」——具体措辞实现时再润色）。
- **按场景引导**：是否联系运维、是否需完成 Wireshark 安装才能抓包、当前是否在「未抓包」下降级运行等。
- **术语兜底**：必要处用**简短副标题 + 一句话解释**或帮助链接，而非大段说明。
- **入口**：提供「另存/打开完整技术报告」类按钮，指向本次任务生成的 `.md`（可说「给技术人员看的详细说明」）。

### 3.4 Markdown 报告建议结构（技术向，可微调）

1. 任务元数据：任务 ID、时间范围（本地时区）、工具版本（主程序、tcping、检测到的 tshark/Wireshark）、主机名、操作系统摘要。  
2. 用户输入：目标、端口列表、选项（超时、次数、IPv4/IPv6 等）。  
3. 本机与出口上下文（第 7.1 节）：网卡、IP、网关、DNS 配置等事实。  
4. DNS（第 7.2 节）：解析结果表、耗时、错误类型。  
5. 连通与质量（第 7.3、7.4 节）：ping/tcping 统计表、RTT 与成功率、抖动等。  
6. 端口结果（第 7.5 节）：逐端口表格（成功/失败、分类、样本数、延迟摘要）。  
7. 抓包（第 7.6 节，若有）：是否启用、tshark 参数摘要、显示过滤器、pcap 路径、关键帧观测事实。  
8. 原始输出索引：各子进程日志文件路径或节选代码块（控制体积时可「仅路径 + 尾部 N 行」策略，实现阶段定）。  
9. 降级与异常：未安装 Wireshark、抓包失败、用户取消等事件记录。  

本版本约束：**必须双输出、Markdown 为技术侧完整版**。

## 4. 产品目标（三类，已定）

| 类别 | 含义 | 主要手段（规划） |
|------|------|------------------|
| **网络连通性** | 本机到目标是否「能到达」、名字能否解析、路径大致是否通 | DNS 解析；ICMP ping（可选，受防火墙影响）；可选 traceroute |
| **网络质量** | 延迟与稳定性，而非仅「通/不通」 | 多次采样 RTT（ping / tcping）；抖动、成功率（等价丢包倾向）；可选结合抓包看重传 |
| **端口连通性** | 指定 TCP 端口是否开放、握手是否完成、拒绝或黑洞形态 | **tcping.exe**（项目内置），按端口批量/串行探测 |

**典型场景**（继承 v1.0）：公网/内网端口是否通、DNS 是否正常、中间设备 RST/黑洞、为上层协议问题建立基线。

## 5. tcping 集成策略（已定）

- **tcping 可执行文件随项目分发**（安装目录或应用目录下固定相对路径调用），**不依赖**用户本机是否单独安装 tcping、也不依赖 PATH。
- 版本锁定：发布包内附带**固定版本**的 `tcping.exe`，并在「关于/诊断信息」及 **Markdown 报告**中展示该版本，便于排障与解析输出格式。
- 调用与解析要求仍适用 v1.0：子进程、超时、多次采样、优先机器可读输出、IPv4/IPv6 策略、归档原始 stdout/stderr。

## 6. Wireshark / tshark / Npcap 获取方式（v1.3 更新）

### 6.1 决策概述

- **不在主程序目录内散装 tshark 及其大量依赖 DLL**；产品**与主程序发布包一体打包经选定的 Wireshark 官方 Windows 安装程序**（例如置于 `ThirdParty\Wireshark\` 或与安装器资源同捆），由 **GUI 引导用户启动该安装程序**完成安装。
- 官方安装向导通常会一并安装 **Wireshark GUI、tshark CLI**，并**引导安装 Npcap**（用户可在向导中勾选/确认）。在用户**同意并完成安装**后，可同时满足自动抓包对 **可执行文件** 与 **抓包驱动** 的两类前提。
- 应用侧通过 **检测** 标准安装路径下的 `tshark.exe`（例如 `%ProgramFiles%\Wireshark\tshark.exe` 及常见变体）决定是否启用抓包；未检测到时展示明确指引：**「一键打开已附带的 Wireshark 安装包」**。

### 6.2 为何该方案能「一并解决」主要矛盾

| 问题 | 该方案的应对 |
|------|----------------|
| 用户未装 tshark、PATH 未配 | 官方安装落到固定目录，应用主动探测绝对路径调用 |
| Npcap 缺失导致抓不了包 | 官方安装流程集中处理 Npcap，减少「只拷贝 exe 忘记驱动」的售后 |
| 用户还需用图形界面深入分析 | 同类安装已带 Wireshark GUI，便于直接打开本工具生成的 pcap |

### 6.3 仍须面对的限制（产品层需兜底的）

- **仍需用户交互与通常在安装时具备管理员权限（UAC）**；用户拒绝安装或企业策略禁止安装时，抓包能力不可用 → **必须保留无抓包降级**（tcping + DNS + ping 等仍可用）。
- **主程序安装包体积**：因内含 Wireshark 官方安装包而显著增大；此为已定 trade-off。**Markdown 报告**中可记录捆绑安装包的版本与文件名校验信息（若实现），便于审计。
- **版本漂移**：用户日后自行升级/降级 Wireshark 可能导致 CLI 行为差异；报告与「关于」中应**记录实际探测到的 tshark 版本**，发布说明中可标明**验证过的 Wireshark 主版本**。
- **许可与再分发**：捆绑官方安装包须遵守 Wireshark 的许可证与官方对再分发的说明（以 [wireshark.org](https://www.wireshark.org/) 与法务审查为准）；**关于**页与 **Markdown 报告**元数据区保持第三方致谢提示。
- **静默/批量部署**：若未来面向 IT 批量装机，可另案评估官方安装器静默参数与组策略场景；**当前默认以交互式引导安装为主叙事**。

### 6.4 与自动化抓包的关系

- 抓包执行方式不变：仍以 **tshark（CLI）** 按 v1.0 规范起止、写 `pcapng`、可选显示过滤器；**可选**在任务结束后用 **Wireshark GUI** 打开同一 pcap。
- `tshark.exe` 来自 **用户通过本工具引导安装的 Wireshark**，由应用**探测路径**，而非随主程序目录携带解压后的 `tshark.exe`。

## 7. 诊断应从哪些维度开展（建议清单）

下列维度是**技术报告**的主体结构；**GUI** 可从中提炼摘要，不必逐段展开。

### 7.1 本机与出口上下文（Local Context）

- **活动网卡**：名称、类型、是否启用；可选：当前选用哪块网卡做探测（高级）。
- **本机 L3 信息**：IPv4/IPv6 地址、子网掩码前缀、**默认网关**。
- **DNS 配置**：当前系统使用的 DNS 服务器列表（仅展示事实，不替代解析测试）。
- **备注**：若存在多网卡/VPN/代理，可用简短提示「结果仅代表当前路由选路下的路径」（代理深层检测可后延）。

### 7.2 名字解析（DNS）

- **解析结果**：A / AAAA 记录、解析到的 IP 列表；解析耗时。
- **失败形态**：NXDOMAIN、超时、无响应等（取决于实现）。
- **与探测一致**：端口与质量类探针实际使用的目标 IP（及地址族）须写入 **Markdown**；**GUI** 用一句话总结「能否解析到可用地址」。

### 7.3 基础连通性（Reachability）

- **ICMP Ping**（可选模块）：若目标允许 ICMP，可看是否可达；若不允许，界面需标注「ICMP 被禁不代表 TCP 不通」。
- **Traceroute**（可选、进阶）：可作为后续版本能力。

### 7.4 网络质量（Quality）

- 基于 **多次 ping**（若启用）与 **每端口多次 tcping**：RTT、成功率、抖动等。
- **说明**：质量结论应区分「ICMP 质量」与「TCP 某端口质量」，二者可能不一致。

### 7.5 端口连通性（Port / Service Reachability）

- 逐端口：握手是否成功、失败分类、RTT 与成功率。

### 7.6 抓包层事实（可选，依赖用户已安装的 Wireshark + Npcap）

- SYN / SYN-ACK / RST / FIN 等观测事实；重传粗粒度标记；**pcapng 绝对路径**（**Markdown 必写**；GUI 可提供「在文件夹中打开」）。

### 7.7 可观测性（元数据）

- **任务 ID、时间范围**；**tcping 版本**；**检测到的 tshark/Wireshark 版本**；是否启用抓包及是否降级。
- 原始日志路径：**Markdown 完整列出**；GUI 默认隐藏路径，通过「给技术人员」入口跳转。

## 8. 总体编排思路（GUI + 双输出）

1. **解析与校验**目标与端口列表；可选先跑 DNS 并展示（同时写入报告模型）。
2. **（可选）若用户启用抓包**：未检测到 `tshark`/Npcap → 引导启动**同捆目录中的** Wireshark 安装程序；用户可取消 → 本轮不抓包（**两路输出均记录降级原因**）。
3. **执行探针**：ping（可选）→ 按端口 tcping。
4. **停止抓包**并落盘。
5. **生成双产物**：① 刷新 GUI（非技术摘要）；② 写出**完整 Markdown 报告**至约定目录（与 pcap、原始日志并列便于打包）。
6. **降级路径**：安装被拒、tshark 失败等：**GUI** 用人话 + 可操作按钮；**Markdown** 记完整事件与技术细节。

## 9. 依赖、分发与合规（v1.3 更新）

- **tcping**：与主程序一起发布，相对路径加载。
- **Wireshark 官方安装包**：**与主程序/公司安装器一并打包分发**；安装后由程序**自动探测** `tshark.exe`；许可与再分发 compliance 见第 6.3 节。
- **企业环境**：禁止安装 Wireshark/Npcap 时，产品仍应在**无抓包**模式下完整提供第 7.1～7.5 节的核心价值，且**两种输出**均说明抓包不可用。

---

## 10. 第一版范围（MVP，v1.3 更新）

- 桌面 GUI（非技术向主视图）+ **每次任务自动生成完整 Markdown 报告**（必选能力）。
- 内置 tcping；**7.2（DNS）+ 7.5（端口）** 为必需；**7.4** 至少基于 tcping 多样本；**7.3 ping** 建议 MVP 即做。
- 抓包：**探测 tshark + Npcap**；否则引导运行**同捆** Wireshark 安装包；失败则降级（双通道均体现）。
- 附带原始日志与 pcap 路径索引（策略见 3.4 第 8 点）。
- **技术侧以 Markdown 为契约**；若需机器可读可在后续版本基于同一模型另导出 JSON，不在 v1.3 强制。

---

## 11. 待拍板的产品决策（v1.3）

1. **tcping 语义**：仅完成握手，还是建立到应用层可读状态（若工具支持）？
2. **抓包粒度**：单次任务单 pcap vs 每端口 pcap。
3. **技术栈**：桌面 GUI 框架（如 .NET WPF/WinUI、Qt、Electron 等）与**大包体**下的安装器体验（进度、磁盘空间提示）。
4. **Markdown 落地**：默认输出目录（用户文档目录 vs 程序数据目录）、文件命名规则（任务 ID + 时间戳）、是否每次诊断覆盖或仅追加。
5. **ICMP/traceroute**：MVP 是否包含系统 `ping`；traceroute 是否排入后续版本。
